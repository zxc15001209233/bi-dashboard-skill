## 根因

1. **入口③越补越长，配套文件没改默认行为。** 禁令在 SKILL.md，默认值在 `templates/`、`layout-patterns.md`、`themes.md`、`chart-patterns.md`。Agent 生成时先打开模板，禁令后置失效。
2. **审核有逃逸口。** 「该块已同构」+「P2 当场修」+ 能力边界表仍写「静态展示完整生成」→ 可以勾通过，也可以无限打磨。
3. **量寸没有可执行步骤。** 写了「铺底写成 px」，没写：先鉴定文件像素/格式、整页截图叠在 `#screen` 还是 `.stage`、壳图非 1920 怎么铺、用什么命令量。

## P0（结构性矛盾：照做也会错）

### P0-1 开篇能力边界 vs 复刻能力边界

`SKILL.md` 开篇表：「静态展示 ✅ 完整生成」。入口③又写 ECharts geo/灯管/电路「允许未覆盖」。

Agent 会按开篇表向用户承诺像素级还原，再用入口③给自己开脱。

**建议：** 开篇表拆两列（主题模式 / 复刻模式）。复刻模式静态展示改为「布局/字号档/图表类型可对齐；材质/三维地图未覆盖」。

### P0-2 Step 4 仍「基于 templates/screen.html」

入口③禁止从 `.panel / .kpi / .topbar` 起稿；Step 4 第一句仍是基于该骨架生成。`themes.md`「面板标准样式（直接套用）」就是玻璃卡。`screen.vue` 的 `PanelBox` 注释仍是「标题条 + 玻璃底」。

**建议：** Step 4 分叉。主题模式才用模板脸；复刻模式只借 `#screen` 适配 + token + 弹窗。`themes.md` 玻璃卡标明「仅主题模式」。

### P0-3 「图表一律从 chart-patterns 改」vs「图表类型跟底图」

`chart-patterns.md` 模板 1 是面积折线，排在最前。无：**柱+线、堆叠柱+线、中国地图 geo**。`layout-patterns.md` 只说地图用 CDN，没有 option。

复刻时 Agent 会拿折线模板顶替柱线（运营大屏已发生）。禁令挡不住「一律从本文件模板修改」。

**建议：** 复刻模式改为「先认图上的 series 类型，再选或新写 option」。补柱+线 / 堆叠柱+线 / geo 地图三份模板。写明 geo ≠ 现网三维地图。

### P0-4 默认栅格 vs 铺底量寸

`layout-patterns.md`、两个模板、骨架预览都写死 `24% 1fr 24%`。入口③禁止用 `24% / 1fr / flex` 瞎估。

无参考图时 24% 合理；有参考图时这是默认列宽的最大来源。

**建议：** 默认三列注明「仅主题模式」。复刻模式禁止套该 CSS，列宽只能量自 overlay。

### P0-5 附件像素未鉴定（本次最大实战坑）

Cursor 对话压缩图常为 **1024×576 JPEG，扩展名仍是 .png**。Skill 写了「&lt;1600 量寸不可靠」，但**没有「落盘后立刻 `file`/`identify`/`sips -g pixelWidth`，禁止信文件名和对话里的 1920」**。

把 1024 拉到 1920 量 gutter，会得到错误列沿（如 73/499 vs 原生 ~88/489）。后续所有「已铺底」都是假量寸。

**建议：** 复刻第一步固定为鉴定源图。输出：路径、真实宽高、格式、是否对话压缩件。宽 &lt; 1600 或 JPEG 冒充 PNG → 停，请用户把原生文件放进仓库再继续。禁止用聊天附件当 1920 真相源。

### P0-6 overlay 坐标系未定义

「用参考图作 1920×1080 半透明底图」未区分：

| 参考图类型 | 应叠在 |
|---|---|
| 含现网壳的整页截图 | `#screen` 1:1 |
| 仅内容区截图 | `.stage`（壳 inset 之内） |
| 壳图本身（如 `bi-bg-x.png` 2460×1384） | `#screen` 铺满，**不是**量列宽的底图 |

把整页截图叠到 `.stage`、或把壳图当内容底图，列沿全错。运营大屏同时有 `1.png`（内容+壳）和 `bi-bg-x.png`（仅壳）。

**建议：** 写死「内容参考图叠哪一层」；壳图只负责外框，禁止用壳图量 KPI/列宽。

### P0-7 「该块已同构」逃逸口

审核骨架允许可见差写「该块已同构」。无操作定义（字号差几 px 算同构？图表类型不同算不算？）。Agent 会空写同构并结论「通过」。

**建议：** 禁止用「已同构」单独过关。必须写 1 条可核对差，或写「未覆盖：…」。清单全是「已同构」= 未审核。

### P0-8 P0/P1/P2 一律当场修 → 无限打磨

运营大屏在引擎边界上把 P2（光晕、1–2px）打到用户叫停。Skill 没有「用户叫停 / 仅剩能力边界 → 结束，禁止再改观感」。

**建议：** 结构/字号档/图表类型/锚点数字当场修；材质/发光密度标未覆盖后停止。用户说停打磨则禁止再改 CSS/图表皮肤。

### P0-9 mock「禁止真实知名企业全称」vs 复刻现网

`mock-data-rules.md` 禁止真实企业名。复刻国药屏必须出现「国药控股」等图上用名。Agent 会改成「云岭生物」破坏锚点。

**建议：** 复刻/现网截图上的组织名、指标名、锚点数字整体照搬；该禁令仅主题模式。

### P0-10 ≥1600 当作可 1:1 量寸

1600×900 拉到 1920 仍畸变，却被写成「原生 ≥1600：1:1 铺底」。真 1:1 只应是 **宽=1920 且高=1080（或用户声明的基准分辨率）**。介于 1600–1919 应声明比例缩放，量寸仅作参考。

### P0-11 description 摘要了能力，未写触发边界

`writing-skills`：description 只写何时用，禁止摘要流程。当前 description 写了「生成风格统一…支持从一句话…可选转 Vue」。Agent 可能只凭 description 套模板，不读入口③。

**建议：** 改成 Use when：用户要数据大屏/驾驶舱/BI 看板，或发了大屏参考图要求照做。不要在 description 里写工作流。

## P1（执行步骤空心，规则无法落地）

### P1-1 量寸没有命令

写了「写成 px 再写 grid」，没给最小脚本：源图铺 `#screen` → Playwright 量元素或读 overlay 像素。Agent 用「目视读图」代替量，等于没铺底。

**建议：** skill 内附 `review/measure-overlay.js`（或一段复制即用的 Playwright），输出顶栏高、三列 x、块 y、标题/KPI 字高 JSON。

### P1-2 「裁切只用 Playwright clip」对磁盘图片未说明前置

要对 PNG 做 clip，须先把图放进 page（img 或 screenshot of file URL）。未写；Agent 会对 HTML 原型 clip，或用 `sips`（已禁止但未给替代完整链）。

### P1-3 「放大 4–12 倍」对低清图制造假锐度

1024 整图放大 8 倍是插值，不是看清灯管和下划线。应：高清才分区 clip；低清禁止声称看清装饰密度。

### P1-4 CountUp 与翻牌冲突

HTML P1：「CountUp / 入场动效缺失」。现网是翻牌盒，不是从 0 滚到目标。复刻时做 CountUp 会破坏翻牌形态。

**建议：** 有参考图则跟图（翻牌/静态/滚动）；CountUp 仅主题模式默认。

### P1-5 时间规则 vs 图上账期

`mock-data-rules.md`「不硬编码过去年份」。复刻必须用图上 `2026-07`。应：图上/文档账期是锚点。

### P1-6 零本地依赖 vs 审核依赖 Playwright

硬性规则 8：HTML 零依赖。Step 5 又要无头浏览器。应写清：交付物 HTML 零依赖；`review/capture.js` 是开发机审核脚本，不进交付 HTML。

### P1-7 壳图尺寸 ≠ 1920

`bi-bg-x.png` 为 2460×1384。未写 `background-size: 100% 100%` 拉伸铺 `#screen`，还是 contain 留边。不写则壳与内容错位，再叠 overlay 更错。

### P1-8 利润绿灯管映射含糊

写了「色相跟图、hex 用 token」，举例 `--data-5`。利润灯管更应对 `--trend-down`（绿）。`--data-3` 在表里是「利润类折线」却是橙色。语义表会把利润做成橙/青。

**建议：** 复刻时按图上色相选 token（绿灯管→`--trend-down` 或 `--data-5`），禁止按「利润类默认 --data-3」。

### P1-9 安装副本与 git 漂移

- `~/.cursor/skills` 与 `~/.agents/skills` 靠手拷；本次审核时 SKILL 已同步，但 **git 工作区仍有未提交的 SKILL/README/checklist**（上次 go 的铺底/能力边界补丁未进 origin）。
- README 写 Gitee + GitHub 双远程，未规定以谁为准。
- 存在 `main` 与 `master` 双分支痕迹。

未提交则 `npx skills add` 装到的仍是旧规则（无「禁止拉伸 1024 当量寸」）。

### P1-10 确认单示例仍是主题模式

Step 2 示例是「三列式 + KPI×4 + 折线」，没有复刻确认单必填项：标题容器形态、源图像素、overlay 叠哪一层、低清声明、每卡结构、图表 series 类型。

Agent 会抄示例，跳过死门。

### P1-11 顶栏/卡内死门篇幅 vs 遵守率

死门要求动手前写出每卡形态。实战中确认单常被缩成布局一句话，然后用户 `go`，skill 虽写「确认单未发出不得开写」，与「用户已 go」冲突时 Agent 会开写。

**建议：** 复刻确认单用检查表（标题形态 / 源图 WxH / overlay 层 / 每卡 4 行）。缺一项不准进入 Step 4。用户提前 `go` 仍先补确认单。

### P1-12 Vue 转工程仍指向玻璃 PanelBox

转 Vue 要求与 HTML 1:1，但骨架注释把 PanelBox 定义成玻璃底。复刻 HTML 若已非玻璃，转 Vue 会被拉回模板脸。
